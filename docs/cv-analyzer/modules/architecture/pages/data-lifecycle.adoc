= Data and Persistence

== Stored data

[cols="1,2,2,2"]
|===
|Data |Location |Key or lifetime |Current behavior

|Original resume
|Configured S3-compatible bucket
|`uploads/<job-id>`
|Written by the `uploader` before the job is queued.

|Extracted text
|Configured S3-compatible bucket
|`results/<job-id>.txt`
|Written by the `extractor` after extraction.

|Redacted extracted text
|Configured S3-compatible bucket
|`results/<job-id>.redacted.txt`
|Written by `piistripper` as a separate best-effort redacted copy; the original extracted text is retained.

|Role-profile scores
|Configured S3-compatible bucket
|`results/<job-id>.skills.json`
|Written by `skillmatcher` from redacted text; contains category scores and matched pattern evidence.

|Extraction job
|RabbitMQ work queue
|`QUEUE_NAME`
|Persistent message in a durable queue, manually acknowledged after success, retry republish, or failed-queue republish.

|Redaction job
|RabbitMQ work queue
|`QUEUE_NAME.pii`
|Persistent message published by the extractor after storing the extracted text; manually acknowledged after redaction, retry republish, or failed-queue republish.

|Skill matching job
|RabbitMQ work queue
|`QUEUE_NAME.skills`
|Persistent message published by piistripper after storing the redacted result; manually acknowledged after scoring, retry republish, or failed-queue republish.

|Failed job
|RabbitMQ failed queue
|`QUEUE_NAME.failed`
|Persistent message retained for inspection or operator-managed requeue.

|Failed redaction job
|RabbitMQ failed queue
|`QUEUE_NAME.pii.failed`
|Persistent message retained for inspection or operator-managed requeue.

|Failed skill matching job
|RabbitMQ failed queue
|`QUEUE_NAME.skills.failed`
|Persistent message retained for inspection or operator-managed requeue.

|Processing status
|RabbitMQ status queue, then uploader memory
|`QUEUE_NAME.events`; in memory for at most 24 hours and up to 10,000 jobs per uploader process
|The uploader consumes and acknowledges status messages. Its status history is lost when the process restarts.
|===

== Temporary files

The extractor downloads each input to a temporary file. For scanned PDFs it renders pages to temporary PNG files before OCR. The code removes these files after processing, but temporary data exists on the extractor host while a job is running.

== Retention and privacy

The services do not implement a retention schedule for uploaded resumes, extracted text, or redacted results. The redacted result is not guaranteed to be anonymous, and the original extracted text remains unchanged.

IMPORTANT: Storage administrators must configure lifecycle expiration and access controls appropriate to their data policy.
