= Extractor Service

The extractor consumes JSON jobs from RabbitMQ, downloads the referenced upload, extracts text, stores the result, and queues redaction.

== Extraction behavior

* For PDFs, it first runs `pdftotext` with layout preservation and UTF-8 output. If the result is blank, it reads the page count with `pdfinfo`, renders pages at 200 DPI with `pdftoppm`, and runs Tesseract OCR on each page.
* For PNG, JPEG, TIFF, and BMP inputs, it runs Tesseract OCR directly.
* It writes non-empty extracted text as UTF-8 plain text to `results/<job-id>.txt`.

The extractor validates that the job ID is non-empty, the bucket equals its configured bucket, and the object key is exactly `uploads/<job-id>`. Each processing attempt has a five-minute timeout.

== Acknowledgement, retry, and failure

The consumer uses manual acknowledgements and a prefetch of one. 

. On success it publishes a persistent redaction job to `QUEUE_NAME.pii` and acknowledges the extraction delivery only after publisher confirmation.
. On processing failure it publishes a `retrying` status and republishes the job with an incremented `x-retry-count` and after publisher confirmation it acknowledges the original. 

It makes up to three retries after the initial attempt. After the last failed attempt, or for malformed JSON, it republishes the message to `QUEUE_NAME.failed` and acknowledges the original.

Retry and failed-queue republishing use publisher confirms. If a republish cannot be confirmed, the original delivery is negatively acknowledged and requeued. A terminal `failed` status is published on exhausted extraction attempts.

Extraction status publishing is best-effort. Once extraction succeeds, the job is not marked complete: piistripper queues matching after writing the redacted copy, and the skill matcher publishes terminal `completed` only after storing role scores.

== Runtime requirements

The extractor requires `pdftotext`, `pdfinfo`, and `pdftoppm` on `PATH`, plus the Tesseract runtime and language data used by the `gosseract` binding. The provided Dockerfile installs Poppler utilities on top of the `otiai10/gosseract` image.

The extractor checks the PDF tools at startup, then connects to RabbitMQ and object storage. See xref:configuration.adoc[configuration] and xref:operations.adoc[operations].

NOTE: Local environment is properly configured with NixOS packages.
