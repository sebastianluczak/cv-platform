Service Contracts

Extraction job

The uploader publishes a persistent JSON message to QUEUE_NAME after storing the upload and confirming the publish:

{
  "id": "<job-id>",
  "bucket": "cv-platform-uploads",
  "object_key": "uploads/<job-id>",
  "content_type": "application/pdf"
}

id is a generated UUID. The extractor requires the bucket to match its configured RUSTFS_BUCKET and requires object_key to equal uploads/<id>.

Redaction job

After storing results/<id>.txt, the extractor publishes a persistent job to QUEUE_NAME.pii:

{
  "id": "<job-id>",
  "bucket": "cv-platform-uploads",
  "object_key": "results/<job-id>.txt"
}

Piistripper requires a UUID id, the configured bucket, and the exact result key derived from that ID. On success it writes the redacted copy to results/<id>.redacted.txt; the source result is retained. Exhausted and malformed redaction jobs are sent to QUEUE_NAME.pii.failed.

Skill matching job and result

After writing the redacted result, piistripper publishes a persistent job to QUEUE_NAME.skills:

{
  "id": "<job-id>",
  "bucket": "cv-platform-uploads",
  "object_key": "results/<job-id>.redacted.txt"
}

The skill matcher validates the UUID, configured bucket, and exact redacted-result key. It writes a versioned JSON object to results/<job-id>.skills.json. The result includes version, job_id, scored_at, and categories; each category has a name, a 1–5 heuristic score, and the matched patterns used as evidence. Exhausted and malformed jobs are sent to QUEUE_NAME.skills.failed.

Status event

The extractor and piistripper publish status messages to the durable QUEUE_NAME.events queue. The uploader consumes these messages and retains the latest one per job in memory.

{
  "job_id": "<job-id>",
  "stage": "processing",
  "message": "We're reading your resume.",
  "attempt": 1,
  "updated_at": "2026-10-14T04:26:44Z"
}

Stages are queued, processing, retrying, redacting, matching, completed, and failed. The extractor reports extraction activity, piistripper reports redaction and matching start, and the skill matcher publishes terminal completion/failure. updated_at is UTC. attempt is the attempt number represented by the status; queued is first recorded by the uploader after job publish confirmation.

Upload response

{
  "job_id": "<job-id>",
  "status": "queued"
}

The browser subscribes to /events?job_id=<job-id> and receives status event objects as SSE data frames.

Status updates are not a durable client-facing event log.
