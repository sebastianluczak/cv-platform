System Context and Runtime Architecture

The current system is an asynchronous file-processing pipeline.

  1. browser interacts with the uploader microservice over HTTP protocol

  2. the uploader and extractor coordinate through RabbitMQ and share an S3-compatible bucket.

The UI is a separate React application.

  1. uses /api/upload and /api/events, so a deployment must route those browser paths to the uploader’s /upload and /events handlers.

This repository does not define that reverse-proxy or gateway configuration yet, it is hardcoded and proxied.

Component responsibilities

Component Responsibility

Browser UI

Selects an allowed file, posts it as multipart form data, then listens to status updates using EventSource.

Uploader

Validates and stores the uploaded file, publishes a persistent extraction job, and streams the latest in-memory status to clients using Server-Sent Events (SSE).

Extractor

Consumes jobs, downloads the referenced upload, extracts PDF or image text, stores the result, and acknowledges or routes the job according to its outcome.

RabbitMQ

Carries extraction jobs, status events, and terminal failed jobs in durable queues.

S3-compatible storage

Stores the original upload and extracted plain text. Both services must use the same bucket and endpoint configuration.
