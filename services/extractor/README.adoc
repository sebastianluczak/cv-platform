= extractor

The extractor consumes upload jobs from RabbitMQ, writes extracted text to object storage, and queues a redaction job for the PII stripper.

== Flow

. consumes a persistent JSON job from the `QUEUE_NAME` queue
. downloads the referenced object from the shared RustFS/S3 bucket
. extracts text from a PDF or runs OCR on an image/scanned PDF
. stores the result at `results/<job-id>.txt`
. publishes extraction and retry status events to `<QUEUE_NAME>.events`
. publishes a confirmed job to `<QUEUE_NAME>.pii` after storing the result
. acknowledges the extraction message only after the redaction job is confirmed

After redaction, piistripper queues the downstream skill matching job. The
overall job is not completed until matching has stored its score result.

Failed jobs are retried up to three times, then moved to `<QUEUE_NAME>.failed` for inspection or manual requeue.

The uploader publishes jobs in this shape:

[source,json]
----
{
  "id": "<job-id>",
  "bucket": "cv-platform-uploads",
  "object_key": "uploads/<job-id>",
  "content_type": "application/pdf"
}
----

== Configuration

Uploader, extractor, piistripper, and skillmatcher must receive the same `RABBITMQ_URL`, `QUEUE_NAME`, `RUSTFS_ENDPOINT_URL`, `RUSTFS_BUCKET`, `RUSTFS_REGION`, `RUSTFS_ACCESS_KEY_ID`, and `RUSTFS_SECRET_ACCESS_KEY` environment variables. `RUSTFS_BUCKET` defaults to `cv-platform-uploads`.

The runtime requires Tesseract and Poppler utilities (`pdftotext`, `pdfinfo`, and `pdftoppm`). The extractor Docker image installs Poppler utilities.
