Service Contracts

Extraction job

The uploader publishes a persistent JSON message to QUEUE_NAME after storing the upload and confirming the publish:

{
  "id": "<job-id>",
  "bucket": "cv-platform-uploads",
  "object_key": "uploads/<job-id>",
  "content_type": "application/pdf"
}

id is a generated UUID. The extractor requires the bucket to match its configured RUSTFS_BUCKET and requires object_key to equal uploads/<id>.

Redaction job

After storing results/<id>.txt, the extractor publishes a persistent job to QUEUE_NAME.pii:

{
  "id": "<job-id>",
  "bucket": "cv-platform-uploads",
  "object_key": "results/<job-id>.txt"
}

Piistripper requires a UUID id, the configured bucket, and the exact result key derived from that ID. On success it writes the redacted copy to results/<id>.redacted.txt; the source result is retained. Exhausted and malformed redaction jobs are sent to QUEUE_NAME.pii.failed.

Skill matching job and result

After writing the redacted result, piistripper publishes a persistent job to QUEUE_NAME.skills:

{
  "id": "<job-id>",
  "bucket": "cv-platform-uploads",
  "object_key": "results/<job-id>.redacted.txt"
}

The skill matcher validates the UUID, configured bucket, and exact redacted-result key. It writes a versioned JSON object to results/<job-id>.skills.json. The result includes version, job_id, scored_at, and categories; each category has a name, a 1–5 heuristic score, and the matched patterns used as evidence. Categories are returned in descending score order, with profile order preserved for ties. Exhausted and malformed jobs are sent to QUEUE_NAME.skills.failed.

Offer matching

After a resume’s skill result is ready, the client submits an offer comparison:

{
  "resume_job_id": "<completed-resume-job-uuid>",
  "offer_url": "https://example.com/jobs/role"
}

POST /matches accepts exactly one of offer_url or offer_text and returns 202 Accepted after the persistent job publish is confirmed:

{"match_id":"<offer-match-uuid>","status":"queued"}

The client polls GET /matches/<match-id>. The worker consumes QUEUE_NAME.offers, reads results/<resume-job-id>.skills.json, and stores the state/result at results/<offer-match-id>.offer.json. Queue jobs contain the match ID, resume job ID, and either offer text or URL. Text is size-limited; fetched pages must be public HTTP(S), use the default port, and pass SSRF-safe resolution/connection checks. The fetcher supports ordinary static HTML, not client-rendered pages. Raw fetched HTML is not persisted.

Required skills are the distinct curated skill patterns identified in an explicit required/must-have section; if none is found, all detected patterns in the offer are used. The percentage is rounded 100 * matched / required; results include matched and missing patterns and their counts. If no requirement patterns are identified the result is unscorable, not 0%. This is heuristic keyword coverage, not an assessment of ability or suitability.

AI resume generation

After a completed offer match, the UI submits an explicit consent affirmation:

{"match_id":"<completed-offer-match-uuid>","consent":true}

POST /weights validates the completed match, stores a queued AI resume artifact, publishes an ID-only persistent job to QUEUE_NAME.aiweight, and returns 202 Accepted with weigh_id. The worker reads the redacted resume, skill result, and retained normalized offer text from storage and stores its Markdown result in results/<weigh-id>.ai.json. The client polls GET /weights/<weigh-id> for queued, processing, completed, or failed. The result artifact and offer text remain subject to object-store lifecycle policy; the platform does not provide user ownership or authorization.

Status event

The extractor and piistripper publish status messages to the durable QUEUE_NAME.events queue. The uploader consumes these messages and retains the latest one per job in memory.

{
  "job_id": "<job-id>",
  "stage": "processing",
  "message": "We're reading your resume.",
  "attempt": 1,
  "updated_at": "2026-10-14T04:26:44Z"
}

Stages are queued, processing, retrying, redacting, matching, completed, and failed. The extractor reports extraction activity, piistripper reports redaction and matching start, and the skill matcher publishes terminal completion/failure. updated_at is UTC. attempt is the attempt number represented by the status; queued is first recorded by the uploader after job publish confirmation.

Upload response

{
  "job_id": "<job-id>",
  "status": "queued"
}

The browser subscribes to /events?job_id=<job-id> and receives status event objects as SSE data frames.

Status updates are not a durable client-facing event log.
