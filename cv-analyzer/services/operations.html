Local Operations

Prerequisites

The development environment is defined by devenv.nix and provides Go, Node.js, Antora, RabbitMQ, and RustFS. The extractor also needs Tesseract and Poppler tools (pdftotext, pdfinfo, and pdftoppm). RabbitMQ and RustFS are started by devenv up in the configured development environment.

Copy .env.dist to .env and provide appropriate local values before starting the environment. The repository template includes the RabbitMQ URL and queue name; storage settings default in the services. Never put production secrets in the template.

Start and build

From the repository root:

devenv up

The devenv processes start the uploader, extractor, piistripper, skill matcher, offer matcher, AIweighter, role insights, frontend, and documentation builder.

The service Dockerfiles expect prebuilt binaries named uploader, extractor, piistripper, skillmatcher, offermatcher, aiweighter, and roleinsights in their respective service directories. task services:uploader:build, task services:extractor:build, task services:piistripper:build, task services:skillmatcher:build, task services:offermatcher:build, task services:aiweighter:build, and task services:roleinsights:build build the binaries and Docker images.

Verification

Run the service unit tests from the repository root:

sh test.sh

Build the Antora site with task docs:build-docs.

Troubleshooting

  • Uploader does not start: check RABBITMQ_URL, QUEUE_NAME, storage endpoint/credentials, and whether the configured bucket can be listed or created.

  • Extractor does not start: verify RabbitMQ settings and that pdftotext, pdfinfo, and pdftoppm are available. Confirm the S3 settings point to the same bucket as the uploader.

  • No redacted result appears: confirm piistripper is running with the same QUEUE_NAME and RUSTFS_* settings; inspect its logs and the durable <QUEUE_NAME>.pii.failed queue.

  • No role scores appear: confirm piistripper and skillmatcher are running with matching RabbitMQ/storage settings; inspect the durable <QUEUE_NAME>.skills.failed queue and the skillmatcher logs.

  • Offer comparison does not complete: confirm the frontend can reach the offer matcher on OFFERMATCHER_PORT, that the service shares the resume’s RUSTFS_BUCKET, and inspect <QUEUE_NAME>.offers.failed. Public offer pages only are supported; private-network destinations, non-HTML content, and SPA-rendered pages are rejected or unsupported.

  • AI resume generation does not complete: confirm the UI can reach AIweighter on AIWEIGHTER_PORT, OPENROUTER_API_KEY is configured, the model name is valid, the service shares the same bucket, and inspect <QUEUE_NAME>.aiweight.failed.

  • Role insights do not complete: confirm the UI can reach roleinsights on ROLEINSIGHTS_PORT, OPENROUTER_API_KEY is configured, the redacted resume exists, the service shares the same bucket, and inspect <QUEUE_NAME>.roleinsights.failed.

  • Upload returns 503: inspect uploader logs and RabbitMQ availability; a message publish confirmation did not arrive.

  • No SSE update appears: confirm that the extractor can publish to QUEUE_NAME.events and that the uploader is consuming that queue. Status state is local to the uploader instance and does not survive its restart.

  • A job repeatedly fails: inspect the extractor logs and the durable QUEUE_NAME.failed queue.
